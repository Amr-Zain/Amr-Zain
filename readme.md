## About me

I am a frontend engineer focused on the point where **business rules, visual language, and human behavior meet**. I build maintainable React and Next.js products for multi-vendor commerce, recruitment operations, classified marketplaces, inspection systems, and schema-driven admin platforms.

My work follows a feature from its API contract to its production interface. That means designing reusable architecture, managing complex server and client state, and treating loading, empty, error, permission, and keyboard states as part of the product—not cleanup work for later.

## This portfolio

The [portfolio](https://amr-zain-portfolio.vercel.app) is itself a focused frontend case study. It combines an editorial monochrome interface with deliberate motion, real project imagery, accessible interaction states, and server-backed contact handling.

| Layer | Implementation |
|---|---|
| Application | Next.js 16 · React 19 · TypeScript · Server Components by default |
| Interface | Tailwind CSS 4 · shadcn/ui on Base UI · Manrope · Instrument Serif |
| Motion | GSAP · `@gsap/react` · React Bits patterns · reduced-motion support |
| Contact | Server Action · SMTP delivery · optional Resend fallback |
| Quality | Responsive layouts · semantic HTML · metadata · JSON-LD · sitemap |

<details>
<summary><strong>Run it locally</strong></summary>

```bash
pnpm install
pnpm dev
```

Copy `.env.example` to `.env.local`. Direct email, GitHub, LinkedIn, project, and résumé links continue to work without mail-provider credentials.

```env
NEXT_PUBLIC_SITE_URL=http://localhost:3000
SMTP_HOST=
SMTP_PORT=587
SMTP_USER=
SMTP_PASS=
CONTACT_EMAIL=
```

Quality gates:

```bash
pnpm lint
pnpm typecheck
pnpm build
```
